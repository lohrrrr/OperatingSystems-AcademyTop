# Практика: модель команды и доступов

Выполняйте задания только на тестовой виртуальной машине. Не создавайте
учётные записи на учебном или рабочем компьютере без разрешения владельца.
Краткая справка приведена в [`CHEATSHEET.md`](CHEATSHEET.md).

Составьте матрицу для четырёх вымышленных ролей: ответственный, разработчик,
тестировщик и наблюдатель. Для каждого каталога проекта определите, кто может
читать, изменять и просматривать содержимое. Затем зафиксируйте ожидаемый
результат каждого теста доступа и сравните его с фактическим.

Не храните в отчёте хеши, пароли и содержимое закрытых системных файлов.
